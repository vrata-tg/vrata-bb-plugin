# Врата AI для bb

Плагин добавляет в bb провайдер **Врата AI (Pi)** со встроенным полноценным **Pi 1.3.0**. Отдельный CLI устанавливать не нужно. Сессии, инструменты, повторы и сжатие контекста выполняет штатный Pi; плагин связывает его с BB. Нужны bb 0.41+ и Node.js 22.19.0+.

## Установка

```bash
bb plugin install npm:bb-plugin-vrata
```

Команда предназначена для опубликованного npm-релиза. Эта ветка готовит первую
npm-поставку; до публикации используйте локальную сборку из раздела «Разработка».
Пакет содержит готовые bundles и сжатый Pi. При первом запуске runtime
распаковывается в приватный кеш машины; загрузка или установка Pi не требуется.
Прямая managed-установка из Git больше не поддерживается: сборщик BB не запускает
подготовку сжатого runtime.

В новом треде выберите провайдер **Врата AI (Pi)**. Если ключ ещё не сохранён, выберите **Ввести ключ и выбрать модель** и отправьте запрос. В треде появятся форма для ключа и список доступных моделей. Выберите модель и уровень ризонинга; исходный запрос продолжится автоматически. Получить ключ можно через [бот Врата AI](https://vrata.tg/bot).

Ключ и адрес API хранятся только на машине треда, в данных плагина, в файле `credentials.json` с правами `0600`. В истории треда сохраняется только факт завершения настройки. Для другой машины ключ вводится отдельно; фоновой рассылки между машинами нет. Pi уже встроен в плагин на каждой машине.

В настройках плагина выберите машину, чтобы добавить, заменить или удалить её ключ. При вводе из треда машина выбирается автоматически по его environment. Проверка и сохранение выполняются на этой машине; сервер bb только передаёт явный запрос формы. Закрытие формы не отменяет уже отправленное сохранение.

Плагин регистрирует 14 моделей из конфигурации гайда Врата AI: Anthropic Messages, OpenAI Responses и OpenAI Chat Completions с указанными в гайде ценами, лимитами и возможностями. Определения находятся в [vrata.ts](vrata.ts). Ключ проверяется read-only запросом `GET /v1/models`. Каталог API не заменяет настройки транспорта и лимитов из гайда. В настройках плагина можно поменять адрес API; по умолчанию используется `https://api.vrata.tg`.

Доступные уровни reasoning определяет закреплённый Pi и конфигурация модели. `xhigh` и `max` показываются только для поддерживающих их моделей.

Подтверждение настройки ждёт проверки и записи ключа на машину текущего треда. Ключ и адрес API применяются вместе со следующей операции; текущий ход и его повторы используют прежнюю пару. Удаление ключа также влияет на новые операции. Модель, уровень ризонинга и история сохраняются для восстановления сессии.

После обновления существующий локальный `bridge-data/credentials.json` продолжает работать без переноса. Прежнюю общую настройку ключа на сервере плагин больше не читает и не рассылает; сам плагин не удаляет её из внутреннего хранилища bb.

## Работа в треде

Ввод, файлы и изображения обрабатываются как в штатном провайдере Pi для bb. Локальные вложения передаются агенту как ссылки на файлы; чтение и обработка изображений выполняются штатными tools Pi. Runtime включает Photon и QuickJS, поэтому обработка изображений и codemode не требуют установки дополнительных пакетов.

Штатные `grep` и `find` используют `rg` и `fd`. Если этих утилит нет в PATH или приватном каталоге Pi, Pi загружает их автоматически с GitHub. Для этой загрузки нужен доступ к сети; сам Pi уже встроен в плагин.

Доступны штатные coding tools Pi и dynamic tools bb с учётом запрещённых инструментов. Тред показывает ответ, рассуждения, результаты инструментов и расход токенов. Steer, остановка, восстановление, fork из checkpoint и ручное/автоматическое сжатие контекста используют native Pi sessions. Неуспешный dynamic tool сохраняет полное содержимое результата, включая изображения.

Pi получает отдельный каталог настроек в данных плагина; существующий `~/.pi` не изменяется. Инструкции проекта, skills и extensions подчиняются штатным правилам доверия Pi. Глобальные настройки отдельной установки Pi не импортируются автоматически. Начальные настройки соответствуют гайду:

```json
{
  "httpIdleTimeoutMs": 3900000,
  "retry": {
    "enabled": true,
    "maxRetries": 20,
    "provider": { "timeoutMs": 3900000, "maxRetries": 0 }
  }
}
```

Повторы выполняет Pi; внутренние повторы SDK провайдера выключены. Восстановление после переполнения контекста и compaction остаются штатными. Доверенные настройки проекта применяются по обычным правилам Pi.

Сессии сохраняются в native JSONL. При первом восстановлении сессии прежнего формата плагин переносит историю и выбранные model/reasoning через Pi SessionManager, сохраняя исходный JSON-файл. Повторный resume использует уже перенесённую сессию.

Поддерживается режим разрешений `full`. Архивирование и переименование средствами провайдера, native user questions и service tier не поддерживаются. Поведение native Pi сравнивается при одинаковой версии, cwd, настройках, trust и extensions.

## Баланс

Внизу левой панели bb выберите машину, чей аккаунт Врата AI нужно проверить. Запрос `GET /v1/account` выполняется на выбранной машине с её локальным ключом. Автоматически следовать за машиной открытого треда эта строка не может: поддерживаемый SDK не передаёт ей контекст треда.

Баланс в рублях включает бонусы и средства в резерве (доступная сумма плюс резерв). При наведении отдельно показаны доступная сумма, оплаченные средства, бонусы, резерв и время проверки. Баланс обновляется после завершения запросов к Вратам (включая ошибки), каждые 30 секунд, по нажатию и при возврате в окно. **Пополнить** открывает [бота Врата AI](https://vrata.tg/bot). До выбора машины запросов нет; при смене выбора прежний баланс сразу убирается.

## Разработка

Правила разработки: [AGENTS.md](AGENTS.md). Полный процесс планирования,
реализации, ревью и доставки через PR:
[vrata-bb-plugin-dev](.agents/skills/vrata-bb-plugin-dev/SKILL.md).

```bash
npm ci
npm run typecheck
npm run build
npm test
bb plugin install path:.
```

Тесты используют синтетические ключи, loopback HTTP, публичный SDK harness и настоящий закреплённый Pi. Они проверяют локальное сохранение и изоляцию машин, onboarding целевого host, native bridge, историю и миграцию, отмену, tools, transport и retries. Отдельная проверка копирует только собранный `host.js` вне checkout и запускает встроенный runtime. Реальный ключ не нужен.

Pi закреплён в devDependencies и включается в готовый `host.js`. `npm run build`
сначала запускает `scripts/vendor-pi-runtime.mjs`: отдельный `npm ci` по lockfile,
побайтная упаковка runtime и notices, Brotli-сжатие и checksum. Затем штатный
сборщик BB встраивает архив в host. Рабочие dependencies генератор не меняет;
архив и metadata игнорируются Git. Повторный запуск использует прежний кеш,
если состав и содержимое runtime не изменились.

`npm pack` запускает build через `prepack` и создаёт готовый tarball. В него
входят app/server/host с metadata, notices и исходники для проверки entrypoints
и server fallback BB. Зависимости Pi, tests, source maps и отдельный runtime
archive не публикуются. Перед выпуском выполняются проверки выше; публикация
`npm publish` и release tag — отдельный шаг. Для ручной проверки уже собранного
пакета без повторной сборки используйте `npm pack --ignore-scripts`.

`npm test` после build собирает общий runtime asset для тестов: import attribute
`type: "bytes"` обрабатывается esbuild, а не самим Node.js. Packaging-тест
устанавливает tarball без scripts/dev dependencies в чистый каталог, проверяет
server fallback и запускает фактический host вне checkout. Полные тексты лицензий
находятся в [packaging/pi/NOTICE.md](packaging/pi/NOTICE.md); одинаковые тексты
хранятся один раз со ссылками из каждого package section. Интеграция с BB
находится в `bridge.ts` и `pi/`: один Pi-процесс на сессию, прямые RPC-команды и
перевод событий. Происхождение кода и лицензия — в [pi/NOTICE.md](pi/NOTICE.md).
