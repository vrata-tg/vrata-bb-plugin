# Async streaming billing gateway review notes

Use this reference when reviewing FastAPI/Starlette/httpx gateways that stream upstream LLM responses while reserving/finalizing user balance.

## High-risk failure modes

- Detached producer + bounded queue can strand holds: if the downstream client disconnects while the producer is blocked on `queue.put`, the producer may never observe a `consumer_active` flag, upstream may stay open, and billing may never finalize/refund.
- Dropped sentinel can hang streams: `queue.put_nowait(None)` inside `suppress(QueueFull)` can lose EOF when the queue is full, leaving the response iterator waiting forever.
- Partial upstream aborts must not bill as success: if upstream raises after emitting bytes but before a terminal success/usage event, refund or apply an explicit partial-charge policy; do not treat `bytes_seen` as successful completion.
- Tail-only usage buffers underbill Anthropic: Anthropic input/cache usage can appear in early `message_start`, while output usage appears near the end. A bounded tail buffer can evict input/cache usage and return a non-estimated output-only usage object.
- Local gateway 429s need protocol-shaped envelopes: OpenAI-compatible routes should return OpenAI-shaped `error`; Anthropic-compatible routes should return Anthropic-shaped `{type:"error", error:{type:"rate_limit_error"...}}`, both with `Retry-After`.
- Pre-upstream estimators must validate numeric request fields (`max_tokens`, `max_completion_tokens`, `max_output_tokens`, `n`) and return controlled `400` instead of uncaught `ValueError`/`TypeError`. Run this validation before reserve/upstream even when the API key has no rate limits; rate-limit gating must not be the only path that validates request shape.
- Validate request-shape fields that are used to mutate upstream bodies (for example `stream_options`) before creating a hold. If mutation like `dict(body["stream_options"])` happens after reserve but before the refund-protected block, malformed input can strand reserved funds.
- Provider transport streaming and router billing streaming must use the same endpoint-aware decision. A provider may correctly buffer JSON for endpoints like embeddings/count_tokens, but a router that branches only on client `stream:true` can still settle the buffered JSON through an SSE parser and misbill.
- Anthropic `messages/count_tokens` should not gain synthetic `stream:false` in the upstream JSON body; strip any client `stream` field and force non-streaming at the transport layer instead.
- OpenAI Responses streaming usage can be nested under `response.usage` in `response.completed` events, not only top-level `usage`; parse both shapes before falling back to estimates.
- Redis-backed limiter paths need explicit connect/socket/command timeouts and a documented fail-open or controlled fail-closed policy. Uncaught Redis errors before reserve/upstream become 500s or stalls for all limited-key traffic.
- RPM-only rate limiting should not serialize/token-estimate the full request body. Estimate tokens lazily only when ITPM/OTPM limits are configured. OTPM-only limits may still need output-token estimates, but should not force full prompt/body serialization when output can be derived from validated max-token fields, defaults, endpoint semantics, and `n`.
- In-memory limiter fallbacks should no-op when no limits are configured and prune old minute buckets; otherwise unlimited keys and minute rollover leak buckets.
- Do not use truthy zero-valued usage objects as sentinels for “estimate exists”. Dataclasses like `NormalizedUsage(protocol=...)` are truthy even when every token count is zero; a fallback expression such as `estimated_usage or safe_fallback(...)` can silently bill terminal streams without provider usage as zero for unlimited or RPM-only keys. Use `None`/explicit flags for precomputed estimates and regression-test terminal-marker-without-usage streams.
- `except Exception` does not catch `asyncio.CancelledError` on modern Python. After a wallet hold is created, route handlers need an explicit shielded cancellation settlement/refund path around provider calls and non-streaming finalize/refund work; otherwise shutdown/client cancellation can leave running logs and reserved funds until stale finalization.
- If a stream has already captured terminal usage, later `GeneratorExit`, send failure, upstream reset, or close callback failure should first attempt complete-capture finalization before refunding. Treat “terminal usage captured, then transport close/reset” differently from “partial stream aborted before terminal marker”.
- A provider may accept `stream:true` but return `200 application/json`. Gateways should buffer and settle such non-SSE responses with the non-streaming normalizer, or reject before sending success bytes; do not run JSON bodies through the SSE incomplete-stream refund path.
- Hook signer and verifier wire formats can drift when the proxy hook is self-contained (for example one side signs as raw hex while the verifier expects a scheme prefix like `v1=<hex>`). Review both ends together and require an integration/contract test where the actual hook client’s signed headers pass the control-plane verifier.
- Final settlement must use the immutable reserve-time price snapshot/request contract. Do not re-resolve mutable model price, route status, or provider mapping during finalize; admin edits between reserve and callback must not change the customer charge or strand successful callbacks.
- Stale-request finalizers need an explicit lease/heartbeat or compare-and-set claim. Selecting `running`/`reserved` rows by `created_at` alone can race active LiteLLM callbacks and refund/finalize the same hold incorrectly. Claims must also be recoverable after worker crash: if a row is moved to `stale_settling` before settlement, the finalizer must be able to reclaim expired `stale_settling` leases and terminal finalize/refund paths must clear the lease.
- When a PR says LiteLLM is the public data plane, verify the legacy/custom FastAPI `/v1/*` gateway is not still publicly reachable with the same customer keys. Otherwise customers can bypass LiteLLM ingress allowlists, LiteLLM budgets/spend telemetry, route controls, and hook contract gates even if the custom gateway still bills.
- Treat LiteLLM/OpenAI request `metadata` as user-controlled unless the code proves otherwise. Billing selectors (`public_model`, `protocol`, path, requested SKU, customer charge fallback) must come from trusted server-side route/model context; require the actual LiteLLM model name to match the approved route before reserving.
- Hook payload serialization must normalize LiteLLM/OpenAI/Pydantic usage objects to plain JSON objects before signing/posting. `json.dumps(..., default=str)` can turn usage into a string, causing the control-plane `usage: dict` validation to reject successful callbacks and strand/refund valid holds.
- Traefik file-provider dynamic configs do not get Docker Compose `${VAR}` interpolation just because the file is mounted. Use Traefik's file-provider Go template syntax such as `{{ env "LITELLM_PUBLIC_HOST" }}` with the env passed to the Traefik container, generate the file before startup, or move the router to Compose labels.
- LiteLLM `max_budget` is cumulative over a budget window, not a remaining-balance field. Do not mirror `wallet.available` directly to `max_budget` after spend; either rely on prepaid hook enforcement or sync `current_period_spend + available` with reset-window semantics.
- Remote LiteLLM team/key creation should be local-first or saga/outbox-backed. Creating remote credentials before the local DB commit can orphan active LiteLLM keys if the local transaction fails; add compensation, quarantine, or reconciliation for remote keys without local mappings. If the remote API returns only a raw key and no stable key id, use the full raw key as the immediate compensation handle and fail creation rather than persisting an undeletable local mapping.
- Snapshot ORM-derived scalars before post-commit best-effort work. In SQLAlchemy async flows, a helper that opens a transaction and then calls `session.rollback()` on failure expires ORM instances even with `expire_on_commit=False`; later synchronous attribute access can raise `MissingGreenlet`, turning an already-committed webhook into HTTP 500. This is especially dangerous when retries see an idempotency event and therefore never schedule the skipped notification. Capture IDs/amounts immediately after commit, then run budget sync/notification lookup using those scalars.
- Keep customer-facing public model names separate from LiteLLM route/model aliases. Local API-key authorization and customer docs usually need `public_model`; LiteLLM admin allowlists need `litellm_model_name`. Bot/admin key creation paths must persist/check the public models while passing LiteLLM aliases to the proxy, and tests should cover the case where the two differ.
- Bot or self-service cabinet actions must enforce the same user-status checks as API-key auth before payments, key creation, and billing mutations. A disabled/inactive user should not be able to mint new LiteLLM-backed credentials through a UI path just because request-time auth rejects old keys.
- Payment “check status” flows should not silently inspect only the most recent open invoice. If users can create multiple pending invoices, checking payment must bind to the selected invoice or scan/credit all uncredited open intents, otherwise an older paid invoice can remain stranded when a newer unpaid invoice exists. Also keep the check idempotent for webhook/reconciler-credit races: if there are no newer pending/paid intents and the latest relevant invoice is already `credited`, return success for that invoice; do not let historical credited invoices satisfy a newer unpaid check.
- Key-details and key-revoke UI flows must bind the selected key identity through confirmation. Showing the latest key but revoking the latest active key can revoke a different credential if the displayed key is already revoked or inactive.

## Safer implementation patterns

- Prefer a direct async iterator over upstream bytes inside the `StreamingResponse` iterator instead of a detached producer task unless the producer lifecycle is tied to the response lifecycle with explicit cancel/await and exactly-once settlement.
- Use `asyncio.shield`/equivalent only around the minimal settlement/refund operation needed to keep ledger invariants on cancellation.
- Keep bounded stream capture that preserves both early and late usage-bearing events, or parse SSE incrementally into a usage accumulator.
- Make transport streaming an explicit provider-adapter decision (`stream=True/False`) rather than inferring solely from a client-controlled `body["stream"]`; some endpoints (e.g. `count_tokens`, `embeddings`) may carry or reject a `stream` field but should not open a streamed upstream response.

## Tests to require

- Client disconnect/cancellation after partial stream bytes: upstream closes and wallet hold is finalized/refunded exactly once.
- Upstream iterator raises before first byte and after partial bytes: log status and wallet state match policy.
- SSE `event:error`, clean EOF without terminal marker, and missing final usage: refund or apply an explicit partial-charge policy; never mark as normal completed usage by accident.
- Long Anthropic stream where early input/cache usage and late output usage are separated by more than the buffer size.
- OpenAI `/v1/responses` streaming `response.completed` with nested `response.usage`.
- Endpoint-aware `stream:true` behavior for non-streaming endpoints such as embeddings and Anthropic `count_tokens`: reject/strip as appropriate before reserve/upstream and verify billing does not use SSE fallback.
- Local OpenAI and Anthropic rate-limit 429 error envelopes and `Retry-After`.
- Malformed numeric request fields and malformed `stream_options` return protocol-shaped `400` before reserve/upstream/log creation, with and without rate limits configured.
- In-memory limiter no-limit no-op and minute pruning; Redis limiter should have separate live/concurrency/error-policy tests when production-critical.
- Hook-client signature contract test: build headers with the actual deployed/self-contained hook client and verify them with the control-plane verifier.
- Reserve/finalize price immutability: reserve with one price/route state, mutate price or disable the route, then finalize and assert the original reserve-time snapshot is used.
- Post-commit side-effect isolation: make a best-effort sync perform at least one DB read and then raise; assert the webhook still returns success, uses pre-snapshotted scalar IDs/amounts, and schedules the notification exactly once. A mock that raises before opening a transaction will miss rollback-expiration bugs.
- Stale finalizer race: active request/callback vs finalizer must settle exactly once using lease/CAS/row-lock semantics; `created_at`-only cutoff is not enough.
